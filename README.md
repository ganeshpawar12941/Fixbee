# Fixbee
College Campus Repair &amp; Complaint Management App

## Standalone mobile builds

Fixbee uses Expo development builds and EAS. The Android package and iOS bundle
identifier are both permanently set to `com.ganeshpawar.fixbee`. Expo Go remains
available for UI work, but native Google sign-in and remote push notifications
require an installed development build.

### Configure Google sign-in and API access

Create a Web OAuth client and an Android OAuth client in Google Cloud Console.
The Android client must use package `com.ganeshpawar.fixbee` and the SHA-1
fingerprint of the EAS Android signing key. Retrieve it with
`npx eas-cli@latest credentials -p android`. For iOS, create an iOS OAuth client
for bundle ID `com.ganeshpawar.fixbee`; set its client ID so the native URL scheme
is generated by `frontend/app.config.js`.

Copy `frontend/.env.example` to `frontend/.env` for local work. For EAS builds,
configure `EXPO_PUBLIC_API_URL` and the Google client IDs in the EAS environment
used by the build (`development`, `preview`, or `production`, as selected in
`frontend/eas.json`). The API URL must be a reachable HTTPS backend origin for a
physical device; localhost is only suitable for local simulators/emulators. Never
put OAuth client secrets or JWT secrets in `EXPO_PUBLIC_*` variables.

On the backend, set `GOOGLE_CLIENT_ID` for existing deployments and allow the
accepted audiences with `GOOGLE_CLIENT_IDS` or the platform-specific
`GOOGLE_WEB_CLIENT_ID`, `GOOGLE_IOS_CLIENT_ID`, and
`GOOGLE_ANDROID_CLIENT_ID`. The server verifies ID tokens and enforces
`COLLEGE_EMAIL_DOMAIN`. Keep CORS configured for Expo web origins; native API
requests do not use browser CORS.

### Link and build with EAS

From `frontend`, authenticate with an Expo account and link the project once:

```sh
npx eas-cli@latest login
npx eas-cli@latest init
```

`eas init` adds the EAS project ID to the Expo app config; push-token registration
needs this ID. Build and install the Android development APK first:

```sh
npx eas-cli@latest build --profile development --platform android
```

For an internal APK without developer tools, use the `preview` profile. The
`production` Android profile produces an app bundle for Google Play. EAS builds
need Android signing credentials; after the first Android build, add its SHA-1
fingerprint to the Android OAuth client and rebuild to enable Google login.

### Push notification credentials

For Android, register an app in Firebase using package
`com.ganeshpawar.fixbee`, download its `google-services.json`, and place it at
`frontend/google-services.json`. The file is git-ignored. For EAS builds, store
it as an EAS file environment variable and set `GOOGLE_SERVICES_FILE` to that
file's path in the build environment. Rebuild and reinstall the native app after
adding or changing this file; it is required to initialize Firebase Messaging.

The app registers the Expo push token with the existing authenticated backend
endpoint. Separately configure Android FCM v1 credentials in EAS and an Apple
APNs key before expecting remote notifications to arrive. iOS device builds
additionally require an Apple Developer account. Notification taps open the
app's notification view.
